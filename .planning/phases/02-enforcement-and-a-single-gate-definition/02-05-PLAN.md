<objective>
Run GOV-01's close sweep: derive the artifact list mechanically, revalidate every
derived artifact against this phase's **final** requirement set, evidence set,
commit anchors and recorded dispositions, and record for each one an explicit
*confirmed current* or *corrected* verdict with the correcting commit.

Purpose: GOV-01's finding, in Alex's framing, is that **checkpoint-derived state
can invalidate previously accurate governance artifacts without changing their
files.** Every one of the four instances it tabulates was accurate when written,
none was edited, each was falsified by a decision taken afterward, and each was
found by accident rather than by a step that looks for them. This is that step.

Output: `02-GOV-SWEEP.md` — the derivation, the evidence table, the re-arm log, and
the disposition of the flagged assumptions this phase carried.

## Why this is its own plan, last

D-16 places the sweep in its own final plan, executed after every other plan has
landed **and after UAT and security sign-off**. Two alternatives were rejected in
discussion, and the reasons are worth restating here because they are the reasons
this plan looks unusual:

- **A section in VERIFICATION.md** was rejected because VERIFICATION.md is itself
  on the sweep's list, so the check and one of its subjects would share a document
   — and because it runs before UAT, where three of the four instances were created.
- **A closing task inside the last code plan** was rejected because it runs before
  the events it exists to catch, which is how all four were missed.

**Accepted cost, stated rather than discovered:** this is a plan that writes no
code, which the executor and verifier machinery is not shaped around. It gets its
own commit and its own summary, and it cannot be skipped by a phase that ran out of
steam.

## What this plan does NOT do

- It does not add, remove or rescope any requirement. That is the halt case, not
  the work.
- It does not touch any file outside `.planning/`. No Go file, no `Makefile`, no
  workflow, no compose file.
- It does not re-run the phase's tests or re-verify its code. Verification is
  `VERIFICATION.md`'s job; this sweep checks whether the **documents** still say
  true things after the checkpoints that closed the phase.
- It does not resolve the flagged assumptions it carries. It puts them in front of
  the developer with what is known about each, which is what "carried, not
  dismissed" has meant since 01-03.
</objective>
