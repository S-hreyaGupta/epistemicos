## 45.5 Resolution work product and operational model

**RS-CORE-1 (resolution only).** Step 12 resolves; it never extracts, never classifies boundary, never verifies.
**RS-CORE-2 (side-effect closure).** The complete canonical effect set per terminal resolution: at most one new `gap_record` (CREATE only); `gap_evidence` entries; record-local `source_spans`; `citation_link` objects; GI-authorized Phase-II `claim_link` structures — `possibly_same_claim` under registered POSSIBLE-A/POSSIBLE-B bases, `related_claim` under a registered related-claim basis, `reason_of` only where authorized; pre-freeze canonical-representative settlement updates on structured records (RS-IDENTITY-7); `CANDIDATE_UNIVERSE_CLOSED` / `CANDIDATE_UNIVERSE_REOPENED` emissions with their exact frozen payloads (RS-EPOCH-2/3); `RESOLUTION_COMPLETE` / `RESOLUTION_BLOCKED` emissions with the frozen attestation payload (RS-COMPLETE-3/4); `gap_processing_envelope` construction/update; lineage (`promoted_from_candidate_ids`); spawned ordinary candidates via `CANDIDATE_CREATED` for qualifying seeds; the single routing-entry update; `state_revision` increment; candidate closure iff `CANDIDATE_ROUTING_COMPLETE(C)` and SM permits. Nothing else is written.
**RS-CORE-3 (Class-A routing outcome exclusivity).** For one Class-A INSTANCE_ROUTING invocation on one `extraction_instance_id`, exactly one outcome is produced: executed CREATE_GAP_RECORD; executed ATTACH_RESTATEMENT; ROUTING_REVIEW_OPEN; or one exact frozen failure/rejection disposition. Never more than one. This rule does not govern RUN_EPOCH or RECORD_RESOLUTION outcome vocabulary — those classes are governed by RS-EPOCH-*, RS-COMPLETE-*, RS-PREC-1, and the frozen State-Machine transition contract.
**RS-CORE-4 (semantic immutability).** relation, knowledge_kind, affected_object, explicitness, context_support, the complete asserted proposition, the normalized proposition, contrast, and persistence reasons are carried into canonical form exactly as frozen by Step-11 semantics — no rewording, no canonicalization of scope/context, no boundary change.
**RS-CORE-5 (gap_id timing).** `gap_id` is minted iff a canonical gap_record is instantiated, within the CREATE transaction, consistent with `A1E-GS-1.4` + `A1E-SM-1.4`. No gap_id exists for ATTACH, review, rejection, or spawn seeds.
**RS-CORE-6 (no verification).** Step 12 never emits `extraction_verified` and never performs Step-13 checks.
**RS-CORE-7 (routing ≠ resolution).** Candidate routing completion — every instance CREATED/ATTACHED and the candidate closed — is NOT Step-12 resolution completion. The record-resolution milestone is separate: `RESOLUTION_COMPLETE` is lawful only under RS-COMPLETE-3's dual attestations for the closure epoch; no single candidate's or instance's terminality implies it.

## 45.6 Identity — applying A1E-GI-1.0

**RS-IDENTITY-1 (input construction).** Construct COMPLETE_PROPOSITION_INPUT exactly as `A1E-GI-1.0` defines, from the frozen `extracted_instance` (complete asserted proposition, normalized proposition, context restrictions preserved). No paraphrase, no trimming.
**RS-IDENTITY-2 (frozen rule, operationalized).** SAME_GAP only if the frozen GI conditions hold: same relation; same knowledge_kind; OBJECT_EQUIVALENT; PROPOSITION_EQUIVALENT over COMPLETE_PROPOSITION_INPUT. A matching `(relation, knowledge_kind, affected_object)` triple alone is NOT sufficient; topical similarity is NOT sufficient; shared constructs are NOT sufficient; semantic-embedding similarity is NOT sufficient; contextual restrictions preserved in the complete proposition may prevent merge (GI-CORE-6 / GI-MERGE-2 anti-erasure honored).
**RS-IDENTITY-3 (Phase-I outcome mapping; GI-CORE-4 consumed exactly).** `identity_decision ∈ {SAME_GAP, DISTINCT_GAP, IDENTITY_UNRESOLVED}`. SAME_GAP → one canonical gap_record: ATTACH_RESTATEMENT(Ii, Gx) where Gx is the canonical cluster target (GI-CLUSTER-1); no same-claim link. DISTINCT_GAP → DO NOT MERGE; CREATE_GAP_RECORD(Ii) where creation is otherwise lawful; then Phase-II routing (RS-IDENTITY-5). IDENTITY_UNRESOLVED → DO NOT MERGE (GI-CORE-3); records remain separate; CREATE_GAP_RECORD(Ii) where creation is otherwise lawful; then Phase-II POSSIBLE-A evaluation (RS-IDENTITY-5). IDENTITY_UNRESOLVED is NOT, by itself, ROUTING_REVIEW_OPEN; DISTINCT_GAP is NOT routing review merely because it is non-SAME_GAP. ROUTING_REVIEW_OPEN is permitted only when GI execution itself cannot produce the frozen deterministic result — a genuine cluster-consistency conflict (GI-CLUSTER-2) or another expressly frozen GI review route. No fourth identity decision exists; never "pick the closest record".
**RS-IDENTITY-5 (Phase-II registered-link routing; GI-LINK-1 symmetry law).** For every evaluated pair whose records remain separate: IDENTITY_UNRESOLVED + registered POSSIBLE-A basis → reciprocal `possibly_same_claim`; DISTINCT_GAP + registered POSSIBLE-B basis → reciprocal `possibly_same_claim`; DISTINCT_GAP + registered related-claim basis → reciprocal `related_claim`; no registered basis → no link. Every symmetric link is written as a reciprocal pair — A links B AND B links A, same registered GI basis, same link kind, basis/source grounding exactly as frozen — committed both-or-neither: if the full symmetric write cannot commit, neither side is written; no one-sided symmetric link state exists. `reason_of` is directional only, exactly as frozen — Step 12 never infers reciprocal semantics for it (GI-LINK-1). Bases are GI-registered facts: Step 12 registers nothing, infers no basis, and writes the resulting links as GS-1.4 `claim_link` structures on both affected canonical records.
**RS-IDENTITY-6 (partition, cluster consistency, fixpoint).** Step 12 executes frozen GI clustering: SAME_GAP verdicts assign canonical clusters (GI-CLUSTER-1); cluster consistency is validated (GI-CLUSTER-2); processing-order invariance holds by construction (GI-CLUSTER-3); the identity partition reaches the deterministic closure-epoch fixpoint (GI-CLUSTER-4): same closed comparison universe + same frozen extracted instances + same GI-1.0 version ⇒ same identity partition, same canonical representative per cluster, same canonical records and links — regardless of processing/arrival order. An unresolved cluster-consistency conflict → ROUTING_REVIEW_OPEN for the affected instance(s).
**RS-IDENTITY-7 (canonical representative; no first-arrival canonicity).** The GI-selected representative (GI-REP-1 frozen precedence, arrival-order-free; GI-REP-2 selection ≠ identity) supplies the ENTIRE canonical semantic payload — no hybrid synthesis (GI-REP-3) — and exactly one `primary` gap-evidence assertion remains — the representative's (GI-REST-2). Arrival order confers nothing. While a record is pre-freeze/structured, Step 12 lawfully updates the canonical representative to the frozen GI selection — payload, primary evidence role, links, lineage, and audit trail through existing fields only; no `representative` schema field is invented. If lawful replacement cannot be performed in the current record state, the existing review/reopen/resolution pathway is used — never silent retention of the first-arriving representative.
**RS-IDENTITY-4 (comparison domain).** Identity runs against the supplied eligible canonical-record set only; Step 12 never expands, samples, or semantically filters that set.

the lawful sequence, exactly as frozen: explicit retraction via `RESOLUTION_BLOCKED` → review → `structured` → ATTACH_RESTATEMENT → epoch re-settlement → dual freeze-stability → `RESOLUTION_COMPLETE`); the frozen-forbidden target states each yield the frozen fail (illegal transition; diagnostic E-RS-ILLEGAL-TARGET): `verifying` → the frozen fail; `verification_review_required` → the frozen fail; `extraction_verified` → the frozen fail; `rejected` → the frozen fail — none is ever silently mutated; the RS-STATE-1 revision vector is satisfied — `candidate_expected_state_revision`, `target_expected_state_revision`, and `counterpart_expected_revisions` for every pre-existing record touched by a mandatory symmetric-link mutation — with any stale object → the whole ATTACH transaction `rejected_stale`: zero source transfers, zero routing update, zero symmetric-link effects; epoch/closure legality holds; and the successful attachment increments the target's `state_revision`, staling any attestation computed before it; the Phase-I identity outcome authorizes SAME_GAP attachment (RS-IDENTITY-3) — never re-derived by similarity at attach time; and the complete transferred restatement source set is present. The frozen payload supports `restatement_sources = 1..n`, never one assumed span. For EVERY transferred restatement source: mint the required target-local source span deterministically (RS-SPAN-1/2); preserve exact source text, offsets, and source identity; add the lawful `gap_evidence` role `restatement`; preserve the complete source/proposition trace for auditability. The complete transfer is atomic: if ANY required restatement source cannot be transferred lawfully, the entire ATTACH event fails to the exact frozen blocker path — no partial evidence attachment, no partial `routing_status` update, no partial target mutation. Attachment is additive: existing canonical source material of Gx is neither destroyed nor rewritten. On success: target revision/audit effects per GS envelope/audit semantics; routing-entry update `Ii → ATTACHED + target_gap_id = Gx` with siblings preserved; `state_revision` increment; `CANDIDATE_ROUTING_COMPLETE(C)` evaluation with same-transaction closure iff TRUE; atomic commit.
**RS-ATTACH-2 (no duplicate canonical gap).** ATTACH never creates a second canonical record for the same gap.
**RS-ATTACH-3 (auditability, per source).** The source `extraction_instance` remains auditable: instance id, bundle id, digest, and — for every transferred restatement source — the exact span provenance persist in the attachment evidence.
**RS-ATTACH-4 (conflicts).** Duplicate identical ATTACH → idempotent same result; ATTACH of Ii to a different second target → `rejected_duplicate_disposition`.

## 45.9 Canonical source-span re-minting

**RS-SPAN-1 (determinism).** Same normalized manuscript snapshot + same `document_id`/`document_version` + same candidate-local offsets + same Step-11 bundle → same canonical source content and the same mapping outcome.
**RS-SPAN-2 (immutability).** Re-minting changes no text, offsets, section identity, paragraph identity, assertion boundaries, context-support boundaries, or proposition wording.
**RS-SPAN-3 (collision and deduplication).** Two different manuscript locations are distinct canonical spans even when their text strings are identical; the same location referenced multiple times within one record deduplicates to one canonical span id, reused deterministically; no cross-record forced deduplication.
**RS-SPAN-4 (failure routing).** Document/version mismatch at invocation is structural (RS-INPUT-2 rejection). Malformed or unmappable offsets inside the frozen instance during a lawful invocation make the canonical payload unconstructible → ROUTING_REVIEW_OPEN (RS-REVIEW-1 class B); the frozen instance is never edited to fit.

## 45.10 Citation resolution

**RS-CITE-1 (deterministic lookup; resolved).** For each Step-11 `citation_mention{source_span_ref; verbatim_citation_text}`, attempt deterministic resolution against the pinned Citation Registry state/version. Resolved → canonical `citation_link` with `resolution_status = resolved`; `registry_citation_id` populated; `citation_span_ref` preserved; GS-1.4 conditional-field requirements followed.
**RS-CITE-2 (unresolved).** Unresolved → `resolution_status = unresolved`; `registry_citation_id` ABSENT; durable `verbatim_citation_text` present; unresolved-review handling follows the existing owned interface. An unresolved citation with its durable verbatim text is a lawful canonical state and, alone, blocks no terminal routing; only a GS-conditional-field impossibility (e.g., required verbatim text absent) is a BLOCKER-R condition.
**RS-CITE-3 (prohibitions).** Never infer a registry id from weak similarity; never silently drop an unresolved citation; never assess citation validity or support; never query external literature for scientific validation.

## 45.11 Persistence reasons and spawns

**RS-PERSIST-1 (reason mapping).** Step-11 persistence reasons map into the canonical record exactly as frozen. A causal persistence reason without an independently asserted deficiency spawns nothing.
**RS-SPAWN-1 (ordinary candidate only).** A `spawn_seed{reason_ref; asserted_deficiency_span_refs; verbatim wording}` containing an independently asserted deficiency becomes an ordinary candidate exclusively through the existing State-Machine `CANDIDATE_CREATED` mechanism — lawful only while the run universe is OPEN (`CANDIDATE_CREATED` under a closed universe is the frozen fail; reopening precedes creation, RS-EPOCH-3): real `candidate_id`; candidate-universe semantics remain those frozen by the State Machine; source trace comes only from the seed's spans; no `gap_id` exists merely because a spawn candidate was created; the spawned candidate enters ordinary boundary/extraction/resolution processing from the start; no direct shortcut from seed to gap_record.
**RS-SPAWN-2 (references and link timing).** The lawful `spawned_claim_ref` is established at spawn per GS-1.4; `reason_of` is established only at the layer and time `A1E-GS-1.4` + `A1E-GI-1.0` + lifecycle rules authorize — between canonical claims once both exist — never at seed time. The distinction between a causal persistence reason without independent deficiency and a persistence reason containing an independently asserted deficiency is preserved exactly.
**RS-SPAWN-3 (emission discipline).** Exactly one spawned candidate per qualifying seed; emission is idempotent, keyed by the source record's identity plus `reason_ref`; spawn emission occurs on or after successful terminal commit and never mutates the routing outcome; a lawfully unconstructible spawn reference discovered before commit is a BLOCKER-R condition (RS-REVIEW-1); a post-commit emission fault is an operational E-RS-SPAWN condition retried idempotently. A qualifying spawn arising after the epoch has closed follows RS-EPOCH-3 — `CANDIDATE_UNIVERSE_REOPENED` (required opaque `reason_code` slot) precedes `CANDIDATE_CREATED`; silent insertion into a closed epoch never occurs. Pre-closure spawn emission for the currently known universe feeds the RS-EPOCH-5 attestation; post-closure spawn-reference settlement feeds RS-COMPLETE-1 — two distinct milestones.

## 45.12 Multi-instance routing

**RS-MULTI-1 (independent resolution; mandatory).** One candidate may carry I(C) = {I1 … IN}; each instance is independently resolved. Lawful mixed example: I1 → CREATED → G1; I2 → ATTACHED → G7; I3 → ROUTING_REVIEW_OPEN; the parent candidate remains nonterminal; after review resolves I3 → CREATED → G9, every instance is terminal and only then may the parent close (MI-10/MI-22/MI-23).
**RS-MULTI-2 (prohibitions).** Step 12 never: chooses a "primary" instance; collapses siblings; closes on the first successful CREATE or ATTACH; transforms review into a terminal disposition; alters the frozen extraction-instance set.

## 45.13 Review and rejection routes

**RS-REVIEW-1 (closed Step-12 blocker taxonomy; Class-A INSTANCE_ROUTING scope).** BLOCKER-S — structural/frozen rejection (RS-INPUT-2 dispositions; no review, no partial effect): Step-11 bundle/digest mismatch; unknown or mismatched `extraction_instance_id`; any RS-STATE-1 revision-vector entry stale; duplicate/conflicting terminal disposition; wrong candidate lifecycle state, `boundary_state ≠ GAP`, or MI-24 field violation; incomplete routing-target payload; ATTACH targeting a frozen-forbidden state — `verifying`, `verification_review_required`, `extraction_verified`, `rejected` — → the frozen fail (illegal transition; diagnostic E-RS-ILLEGAL-TARGET); POST-closure ATTACH targeting `resolved` → `rejected_illegal` (lawful path = explicit `RESOLUTION_BLOCKED` retraction → review → `structured` → ATTACH). BLOCKER-R — lawful INSTANCE_ROUTING blocker → `ROUTING_REVIEW_OPEN` (lawful invocation, terminal resolution not lawfully producible): a genuine GI execution conflict — an unresolved cluster-consistency conflict (GI-CLUSTER-2) or another expressly frozen GI review route — prevents the deterministic Phase-I/Phase-II result; lawful canonical-representative replacement is impossible in the current record state (RS-IDENTITY-7) pending the existing pathway; the required canonical payload cannot be created without violating `A1E-GS-1.4`; any required restatement source cannot be transferred lawfully — the entire ATTACH fails to this route with zero partial effects; deterministic span mapping fails inside the frozen instance; the citation-resolution state prevents a required canonical construction (RS-CITE-2 boundary case only); a spawn reference cannot be completed lawfully before commit. NONBLOCKING — ordinary representable conditions, not blockers: IDENTITY_UNRESOLVED and DISTINCT_GAP Phase-I verdicts (ordinary CREATE + Phase-II routing); a PRE-closure ATTACH to a lawful `resolved` target (the frozen structured-regression path, not a blocker); an unresolved citation with durable verbatim text; nonterminal sibling instances; open review on siblings. IDENTITY_UNRESOLVED and DISTINCT_GAP are never, by themselves, BLOCKER-S or BLOCKER-R members. ROUTING_REVIEW_OPEN belongs exclusively to Class-A INSTANCE_ROUTING: RUN_EPOCH and RECORD_RESOLUTION failures are never routed to review — they take the exact frozen dispositions. This set is closed; technical errors are not promoted to semantic review.
**RS-REVIEW-2 (review mechanics).** Review entry uses only the existing `routing_review_required` pathway and vocabulary: the instance's routing entry is set `ROUTING_REVIEW_OPEN` with no `target_gap_id`; siblings preserved; no new states, no new runtime reason codes, no Step-13 verdict codes.
**RS-REVIEW-3 (re-entry).** A review resolution re-enters the RS-PREC-1 procedure fresh against current frozen inputs; prior failed attempts persist only as audit trail, never as bias.

## 45.14 State, revision, concurrency, idempotence

**RS-STATE-1 (transaction-class state/revision guards).** Every mutating Step-12 transaction carries expected state/revision guards for EVERY pre-existing mutable object actually affected by THAT transaction class; no candidate guard is universally required. **Class A — INSTANCE_ROUTING:** always `candidate_expected_current_state = gap_resolving` and `candidate_expected_state_revision`; where ATTACH applies, `target_expected_current_state` and `target_expected_state_revision`; where reciprocal Phase-II links mutate pre-existing records, `counterpart_expected_revisions = { gap_id → expected_state_revision }` plus any frozen state guards those counterpart mutations require; where epoch legality matters, the current universe status and the current `closure_id` iff CLOSED. Any stale pre-existing object → `rejected_stale`, zero transaction effects; any state mismatch for which the frozen SM specifies fail → the exact frozen fail, zero transaction effects. **Class B — RUN_EPOCH:** `candidate_expected_state_revision` is NOT required; the frozen `gap_run` guards are. Every run-level transition request carries `run_id`, `run_expected_current_state`, and `run_expected_state_revision` = the current `gap_run.state_revision` — the frozen §32.14 request discipline applies to the run artefact, whose transition audit carries required `from_state_revision`/`to_state_revision` fields. For `CANDIDATE_UNIVERSE_CLOSED`: `run_expected_current_state` = the frozen universe-open run state; the frozen next/current `closure_id` semantics; the closure preconditions/attestations and exact frozen payload. For `CANDIDATE_UNIVERSE_REOPENED`: `run_expected_current_state` = the frozen universe-closed run state; the current `closure_id` being invalidated; the required opaque `reason_code` slot; every other frozen payload element. Either an expected-state mismatch OR a `run_expected_state_revision` mismatch → `rejected_stale`; zero run/epoch effects. `gap_run` expected state + expected state_revision provide the transition concurrency protection; `closure_id` identifies the current closure epoch and is additionally checked where the event contract requires it — it never substitutes for the revision guard. A missing or malformed payload element that is not a stale guard mismatch → the exact frozen fail; zero epoch effects. **Class C — RECORD_RESOLUTION:** `RESOLUTION_COMPLETE` requires `expected_current_state = structured` + `record_expected_state_revision`; `RESOLUTION_BLOCKED` requires `expected_current_state = resolved` + `record_expected_state_revision`. Revision mismatch → `rejected_stale`; state mismatch → the exact frozen fail; zero partial event effects in either case. **Frozen request interface (alias bridge).** Every actual State-Machine transition request Step 12 emits carries the frozen fields `expected_current_state` and `expected_state_revision` (§32.14): INSTANCE_ROUTING candidate transition — `expected_current_state` = `gap_resolving`, `expected_state_revision` = the candidate's `state_revision`; RUN_EPOCH transition — `expected_current_state` = the current `gap_run` state, `expected_state_revision` = `gap_run.state_revision`; RECORD_RESOLUTION transition — `expected_current_state` = `structured` (RESOLUTION_COMPLETE) or `resolved` (RESOLUTION_BLOCKED), `expected_state_revision` = the record's `state_revision`. The prefixed names `candidate_expected_*`, `target_expected_*`, `counterpart_expected_*`, `run_expected_*`, and `record_expected_*` are Step-12-local labels used only to disambiguate multiple guarded artefacts inside one transaction; they do not replace, extend, or rename the frozen State-Machine `expected_current_state` / `expected_state_revision` request fields. After any stale rejection the worker reloads ALL affected current objects, recomputes as required, and retries as a FRESH invocation — a pre-reload result is never assumed valid. The frozen serialized example carries exactly: revision 20 → 21 (first sibling commit); parallel sibling at 20 → `rejected_stale` → reload → commit 21 → 22.
**RS-STATE-2 (atomicity by transaction class).** Transaction atomicity is evaluated over the object set of the invoked class, commit-or-nothing, storage technology unconstrained; the normative grounding is class-specific. CLASS A — INSTANCE_ROUTING (CREATE_GAP_RECORD / ATTACH_RESTATEMENT): atomicity follows `A1E-SM-1.4` MI-22 and all carried record-side atomicity — candidate routing-entry mutation, candidate revision, CREATE/ATTACH record effects, target effects, and mandatory reciprocal counterpart effects commit all-or-nothing; candidate closure occurs in the same transaction iff the frozen conditions hold; no orphan gap_record even where deterministic `gap_id` generation was precomputed; no one-sided link; no partial source transfer. CLASS B — RUN_EPOCH (`CANDIDATE_UNIVERSE_CLOSED` / `CANDIDATE_UNIVERSE_REOPENED`): atomicity follows the carried frozen State-Machine `gap_run` transition, revision-protection, and transition-audit semantics (SM v1.3 §32.6 run rows; §32.14; the transition-audit schema with its required `from_state_revision`/`to_state_revision` fields) — the run state transition, the `state_revision` increment, the closure/reopening epoch mutation, and the required event/audit effects commit atomically as frozen; no Class-A routing mutation occurs in the same transaction merely because reopening may subsequently permit a `CANDIDATE_CREATED` event — subsequent candidate creation is a separate frozen event; MI-22 is not the basis. CLASS C — RECORD_RESOLUTION (`RESOLUTION_COMPLETE` / `RESOLUTION_BLOCKED`): atomicity follows the carried frozen State-Machine record-transition, revision-protection, and cross-artefact/event semantics (SM v1.3 §32.6/§32.7 record rows; §32.14) — the target gap_record/envelope transition and required audit/event effects commit atomically; no candidate-routing mutation; MI-22 is not the basis. Not all Step-12 transactions are CREATE/ATTACH transactions.
**RS-STATE-3 (idempotence and the conflict quartet).** An exact retry of an identical committed request returns the identical result with no additional effect. Conflicts, all → `rejected_duplicate_disposition`: CREATE then ATTACH on the same Ii; ATTACH then CREATE on the same Ii; ATTACH Ii→G1 then ATTACH Ii→G2; a non-identical duplicate CREATE.
**RS-STATE-4 (order independence).** Same-revision parallel sibling writes serialize; after all instances reach terminal status, the final semantic `routing_set` is independent of sibling execution order — logically commutative, physically serialized.

## 45.15 Traceability

**RS-TRACE-1 (nothing invented, nothing lost).** Created records carry lineage `promoted_from_candidate_ids`; attachment targets carry auditable attachment effects; every routing entry's outcome is traceable to its `extraction_instance_id`, `extraction_bundle_id`, and `structured_output_digest`; all canonical source/semantic content traces to frozen Step-11 representation; no semantic or source information is invented or lost in resolution.

## 45.14A Candidate-universe closure epochs

**RS-EPOCH-1 (open epoch).** While the run's candidate universe is OPEN: ordinary candidate creation remains lawful as frozen (detection and qualifying Step-12 spawns); Step-12 per-instance routing proceeds; `identity_routing_freeze_stable` cannot be TRUE — the frozen State Machine makes emission of `RESOLUTION_COMPLETE` while the universe is open an illegal transition, and every freeze-stability attestation must cite a current `closure_id`, which an open universe does not have.
**RS-EPOCH-2 (CANDIDATE_UNIVERSE_CLOSED).** Step 12 emits `CANDIDATE_UNIVERSE_CLOSED` only when the frozen preconditions hold: no run candidate is in `detected`, `gap_extracting`, or `extraction_review_required`, and the required completion attestations are present. The emission carries exactly the frozen payload — `run_id`; `closure_id` (next epoch); the Step-10 detection-completion attestation reference; the Step-12 spawn-emission-completion attestation (RS-EPOCH-5); the candidate census digest (ids/count at closure); component versions. Before commit the emission validates the frozen `gap_run` transition guard — `run_expected_current_state` (universe-open) and `run_expected_state_revision` — and any stale guard → `rejected_stale`, no closure transition; event-specific payload and preconditions are validated separately. `CANDIDATE_UNIVERSE_CLOSED` is never emitted unless the invocation supplies exactly these frozen inputs proving detection completion, spawn-emission completion, the current universe identity, `run_id`, and the frozen `closure_id` semantics; a missing or mismatched payload element → the frozen fail (precondition/payload violation); no epoch transition; nothing inferred. Closure fixes the run's candidate universe under that `closure_id`; the closed epoch becomes the GI-CORE-5 comparison universe for cluster/fixpoint execution; candidate creation the frozen State Machine prohibits under a closed universe never occurs silently — the attempt is the frozen fail (reopen first).
**RS-EPOCH-3 (CANDIDATE_UNIVERSE_REOPENED; post-closure creation).** If a lawful event requires creating another candidate after closure — including a qualifying persistence spawn — Step 12 first emits `CANDIDATE_UNIVERSE_REOPENED` with the frozen payload: `run_id`; the current closed `closure_id` being invalidated; the required `reason_code` SLOT — the frozen `CANDIDATE_UNIVERSE_REOPENED` event requires it, and Step 12 treats the value as OPAQUE: Step 12 does not define the vocabulary, validate membership, normalize the value, map synonyms, interpret semantic meaning, or invent values; reason-code vocabulary and semantics remain downstream-owned by Step 13 / KB-6 as frozen; and any other frozen required event payload. A missing payload element (including an absent `reason_code` slot or an absent current `closure_id`) → the frozen fail because the event payload is incomplete; no epoch transition; nothing inferred. A present `reason_code` receives no vocabulary-membership judgment from Step 12. The frozen reopening triggers include a `HUMAN_CORRECT` delta introducing a new spawn assertion, which obliges reopening before the spawn candidate is emitted; the reason value accompanying any trigger remains opaque to Step 12. Before commit the emission validates the frozen `gap_run` transition guard — `run_expected_current_state` (universe-closed) and `run_expected_state_revision` — and any stale guard → `rejected_stale`, no reopening transition; payload validation is separate. Effects, exactly as frozen: the universe reopens; epoch N is invalidated; every identity attestation citing epoch N is stale by construction; the frozen resolution-invalidation cascade applies (RS-COMPLETE-4). Only then does `CANDIDATE_CREATED` proceed. Never is a candidate inserted into a closed epoch.
**RS-EPOCH-4 (re-settlement, re-closure, re-attestation; anti-equations).** After reopening: newly lawful candidate creation proceeds; Step 12 reruns candidate routing; the GI partition and the GI-CLUSTER-4 fixpoint are recomputed for the next closed epoch; representative selection (GI-REP-1/3) is recomputed; Phase-II links and spawn references are re-settled; both freeze-stability attestations are recomputed citing the new `closure_id`; `RESOLUTION_COMPLETE` may be re-emitted only after all frozen conditions are restored. Reopening never touches `extraction_verified` records — they froze under a then-valid epoch. Candidate routing completion ≠ candidate-universe closure; candidate-universe closure ≠ `RESOLUTION_COMPLETE` — three separate milestones, never equated.
**RS-EPOCH-5 (Step-12 spawn-emission-completion attestation; the predicate consumed by CANDIDATE_UNIVERSE_CLOSED).** For run R, the attestation is TRUE iff, over the complete candidate universe currently known for the OPEN epoch: (1) every Step-11 extraction bundle already eligible for Step-12 resolution has been inspected for all Step-12-owned persistence spawn obligations; (2) every qualifying spawn obligation derivable from that currently known universe has reached exactly one lawful frozen outcome — the required spawned candidate was emitted exactly once through `CANDIDATE_CREATED`, or no spawned candidate is required under the frozen persistence rules; (3) no pending Step-12 operation over the currently known universe can still emit another candidate without first requiring the frozen `CANDIDATE_UNIVERSE_REOPENED` pathway after closure; (4) every qualifying spawn already emitted is represented in the current candidate universe; (5) the attestation is bound to `run_id`, to the exact pre-closure universe identity the frozen closure contract binds — the candidate census digest (ids/count at closure) — and to the component versions the frozen payload carries; (6) the attestation is INVALID if the pre-closure candidate universe changes before `CANDIDATE_UNIVERSE_CLOSED` commits. **Distinction (never aliased):** this PRE-closure attestation answers "have all currently knowable candidate-producing spawn obligations been exhausted sufficiently to close the universe?" and permits `CANDIDATE_UNIVERSE_CLOSED`; `spawn_reference_freeze_stable` (RS-COMPLETE-1) is the POST-closure settlement attestation answering "are all Step-12-owned spawn references freeze-stable for this closure epoch?" and contributes to `RESOLUTION_COMPLETE`. Neither substitutes for the other.

## 45.15A Resolution completion and retraction

**RS-COMPLETE-1 (spawn_reference_freeze_stable).** TRUE iff: every qualifying persistence spawn has been deterministically emitted; every Step-12-owned `spawned_claim_ref` is established; no unresolved Step-12-owned spawn-reference blocker remains; no pending spawn operation can still change the A.1-E-owned canonical/link structure for the current closure epoch; and no qualifying spawn obligation remains that would require reopening the closed epoch. This POST-closure settlement attestation is distinct from the PRE-closure RS-EPOCH-5 spawn-emission-completion attestation; they are never aliases and neither substitutes for the other.
**RS-COMPLETE-2 (identity_routing_freeze_stable).** TRUE iff: the run's candidate universe is CLOSED via `CANDIDATE_UNIVERSE_CLOSED` and the attestation cites the CURRENT `closure_id` (an attestation over an open universe or a stale epoch is impossible by construction); every Step-11 extraction instance has terminal routing CREATED or ATTACHED; no ROUTING_REVIEW_OPEN remains; the GI Phase-I identity partition is complete; SAME_GAP clusters are consistent (GI-CLUSTER-2); processing-order invariance holds by construction (GI-CLUSTER-3); the deterministic closure-epoch fixpoint is reached (GI-CLUSTER-4); canonical representative selection is settled, with the representative supplying the entire canonical payload, and reflected in the canonical records (GI-REP-1/3; RS-IDENTITY-7); all required ATTACH_RESTATEMENT effects are complete; all GI-authorized Phase-II routing owned at this stage is settled with every symmetric `possibly_same_claim` / `related_claim` pair fully reciprocal — a one-sided symmetric link anywhere in the epoch makes this attestation FALSE until reconciled — and `reason_of` links directional as frozen; and no remaining within-scope identity/routing event can change the A.1-E-owned canonical record topology for the current closure epoch.
**RS-COMPLETE-3 (RESOLUTION_COMPLETE emission).** Only when BOTH attestations are TRUE may Step 12 emit `RESOLUTION_COMPLETE(spawn_reference_freeze_stable = true, identity_routing_freeze_stable = true, …required frozen SM payload…)`, transitioning a lawful `structured` record to `resolved` exactly as the State Machine defines; the `identity_routing_freeze_stable` component cites the run's current `closure_id` — emission while the universe is open, with a missing epoch citation, or citing a non-current epoch is the frozen illegal transition and is never attempted. The event request declares `expected_current_state = structured` and `record_expected_state_revision` = the record's current `state_revision` per the frozen §32.14 discipline; a revision mismatch → `rejected_stale` with zero event effects — including the frozen case of an attestation computed at revision N after a T1 attachment moved the record to N+1; a state mismatch → the frozen fail with zero event effects. Never emitted merely because one candidate or one extraction_instance has terminal routing (RS-CORE-7). No new lifecycle events or states are invented.
**RS-COMPLETE-4 (RESOLUTION_BLOCKED retraction and rerun).** If a record previously `resolved` loses either attestation before verification through a lawful event — including a lawful pre-closure ATTACH to it, closure-epoch reopening, or spawn unsettlement — Step 12 emits `RESOLUTION_BLOCKED` using the existing frozen State-Machine path. On `CANDIDATE_UNIVERSE_REOPENED`, Step 12 is spec-obligated (the frozen deterministic, backstopped cascade) to emit `RESOLUTION_BLOCKED` for every pre-freeze record whose identity attestation cites the invalidated epoch; `extraction_verified` records are never touched — they froze under a then-valid epoch; rerun semantics are exactly as frozen; after settlement both attestations are re-evaluated and, when both are TRUE again, `RESOLUTION_COMPLETE` is emitted again. The retraction request declares `expected_current_state = resolved` and `record_expected_state_revision` = the record's current `state_revision`; a revision mismatch → `rejected_stale`, a state mismatch → the frozen fail, each with zero event effects. Never used for ordinary stale requests or normal candidate routing review.

## 45.16 Deterministic procedure

**RS-PREC-1 (transaction-class dispatch procedure).** **RS-0** determine and validate `transaction_class` from the invocation (RS-INPUT-1); exactly one class is selected; no invocation executes steps of more than one class, except where a frozen event explicitly triggers a later, separate lawful transaction (e.g., the reopening cascade's RESOLUTION_BLOCKED emissions, each a Class-C transaction; a post-reopening CANDIDATE_CREATED, a separate frozen event). **CLASS A — INSTANCE_ROUTING** (CREATE_GAP_RECORD / ATTACH_RESTATEMENT / ROUTING_REVIEW_OPEN). A1 validate Class-A inputs and the Class-A state/revision guards (RS-INPUT-2; RS-STATE-1, Class A clause). A2 validate the Step-11 handoff — `routing_set`, `extraction_bundle_id`, `structured_output_digest`, `extraction_instance_id` (RS-HANDOFF-1/2). A3 load the exact frozen `extracted_instance`. A4 construct COMPLETE_PROPOSITION_INPUT (RS-IDENTITY-1). A5 apply GI Phase I over the current lawful epoch universe (RS-IDENTITY-2/4/6). A6 route the exact Phase-I result (RS-IDENTITY-3): SAME_GAP → ATTACH path; DISTINCT_GAP → CREATE + Phase-II path; IDENTITY_UNRESOLVED → CREATE + POSSIBLE-A path; genuine GI execution conflict → ROUTING_REVIEW_OPEN. A7 apply Phase-II registered links, reciprocal per RS-IDENTITY-5. A8 resolve citations (RS-CITE-1/2). A9 re-mint spans (RS-SPAN-1/2/3). A10 prepare persistence/spawn effects (RS-PERSIST-1; RS-SPAWN-1/2). A11 any lawful BLOCKER-R condition of RS-REVIEW-1 → ROUTING_REVIEW_OPEN; skip the mutation transaction. A12 execute the atomic CREATE / ATTACH / reciprocal link effects (RS-CREATE-1; RS-ATTACH-1). A13 update exactly one routing entry. A14 preserve siblings. A15 increment the applicable revisions as frozen. A16 evaluate `CANDIDATE_ROUTING_COMPLETE(C)`. A17 close the candidate iff the frozen State Machine permits (same transaction, MI-22). A18 persist the exact audit outcome. STOP Class A. **CLASS B — RUN_EPOCH** (`CANDIDATE_UNIVERSE_CLOSED` / `CANDIDATE_UNIVERSE_REOPENED`); Class B never requires `candidate_id`, `boundary_state`, `extraction_instance_id`, `routing_set`, the Step-11 bundle, COMPLETE_PROPOSITION_INPUT, or per-instance GI evaluation. Closure path: B1 validate the transaction class, `run_expected_current_state`, and `run_expected_state_revision` (RS-STATE-1, Class B clause). B2 any stale state/revision mismatch → `rejected_stale`; STOP.
