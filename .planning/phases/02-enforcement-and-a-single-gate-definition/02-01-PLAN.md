<objective>
Turn the escalation mechanism Phase 1 built into enforcement: rename the flag to
`EPISTEMIC_OS_TEST_REQUIRE_ENV`, give all three escalated paths one shared failure
preamble that names the flag and prints its value, guard the rename with a
permanent tripwire, and reshape `make gate` into a strict gate that demands a
running PostgreSQL and reports an unmet environment condition through `testenv`
rather than through `golang-migrate`.

Purpose: this is the plan that makes `make gate` mean something. Every other plan
in this phase either proves this one's behavior (02-02), collapses CI onto it
(02-03), or governs the paperwork around it (02-04, 02-05). Phase 3's three
proofs bind to the literal flag name and the literal message shapes this plan
fixes.

Output: a strict `gate` target, a new `env-preflight` target, and a `testenv`
package whose three escalated failures speak with one voice.

## Decisions this plan makes (planner's discretion, flagged for review)

CONTEXT.md locks the mechanisms; these are the choices it left open. They are
surfaced because 02-02, 02-03 and Phase 3 all bind to them.

1. **The preflight target is named `env-preflight`, not `preflight`.** A package
   named `internal/platform/preflight` already exists in this repository and does
   something entirely different — startup-time Mathpix credential probing for the
   running service. A Make target called `preflight` would read as an invocation
   of it. `env-preflight` also matches the flag's post-GATE-07 name, whose whole
   point (GATE-07) is that the scope is environment-wide rather than
   database-only. Rated `reversible`.
2. **`escalationPreamble()` is a function, not a constant**, because it must read
   the flag's current value at failure time (GATE-06 requires the *value* be
   printed). It takes no parameters, so there is no argument position a DSN could
   occupy. Rated `reversible`.
3. **`renameTripwireMsg` is a pure function over the two flag values**, built by
   compile-time concatenation of constants with no format verbs — the same
   discipline `unparseableURLMsg` uses. Its parameters decide the branch and never
   reach the output. This is what makes D-10's required test possible without
   driving a `*testing.T` from outside, and it reuses the `preambleInvariant`
   pattern Phase 1 established (a pure decision function exercised against
   synthetic inputs, which retired the mutate-and-restore pattern). Rated
   `reversible`.
4. **The reachability assertion is `TestPoolReachesDatabase`, which runs
   `SELECT 1` through the pool** rather than merely calling `Pool` and discarding
   the result. A call whose result is discarded proves the helper did not fail; a
   query proves the pool is usable. Rated `reversible`.

## Ordering correction, resolved in D-03's favour

CONTEXT.md's D-02 summary line reads
`vet → gofmt → build → $(MAKE) migrate → preflight → $(MAKE) test`, while D-03's
body states that the preflight runs **before** `migrate` and gives the reason: with
migrate ahead of it, `store.RunMigrations` becomes the first reporter for GATE-01
and GATE-02, and its unaudited `new migrator: %w` text names neither the variable
nor the host in the requirements' terms. D-03 states the reason, so D-03 governs.
The developer confirmed this ordering after CONTEXT.md was written.

**The order this plan implements is: vet → gofmt → build → env-preflight →
`$(MAKE) migrate` → `$(MAKE) test`.**
</objective>
