## 46.2 Core verification principle

**VS-CORE-1 (verify the extraction, never the science).** Step 13 verifies the extraction. It never verifies whether the manuscript's gap claim is scientifically true. Step 13 MAY ask: did the manuscript actually assert this deficiency; is the extracted assertion span faithful; is the gap really GAP under `A1E-BR-1.2`; is explicitness correct; are relation and knowledge_kind supported by the source wording; is affected_object source-grounded; is the preserved proposition complete; is normalization faithful; was contrast captured faithfully; were citation references captured/resolved faithfully; were persistence reasons and spawned claims handled correctly; was identity/restatement routing consistent with frozen GI rules; is the canonical representative correct; is the record structurally ready to freeze. Step 13 MUST NOT ask: does the gap actually exist in the literature; is it novel; is it important; does the cited paper support the claim; is the theory good; is the method appropriate; does the RQ follow from the gap; does the contribution address the gap; is the manuscript publishable; what A.1-C type/mode/construction is this. Those belong downstream.
**VS-CORE-2 (no second extraction pipeline).** Step 13 re-evaluates frozen rules against the EXISTING canonical record only. It never emits a replacement structured extraction, detects another gap, generates alternative candidates, automatically overwrites relation/kind/object, automatically creates an alternative canonical record, or automatically merges/splits canonical records. A verifier discrepancy produces `review_required` or, only under VS-REJECT-1, `reject`; correction remains evented, human, phase-correct.
**VS-CORE-3 (three verdicts only).** The VERIFICATION_SPEC-owned `verdict_code` set is exactly {`pass`, `review_required`, `reject`}, mapping exactly: aggregate pass → `VERIFICATION_PASS`; aggregate review_required → `VERIFICATION_REVIEW_REQUIRED`; aggregate reject → `VERIFICATION_REJECT`. `review_required` is never equated with the UNCERTAIN candidate boundary state — different lifecycle concepts. No fourth semantic verdict exists: `warning`, `partial_pass`, `probably_pass`, `low_confidence`, `not_sure`, `unsupported`, and every fail-but-review variant are prohibited vocabulary.
**VS-CORE-4 (human events consumed, never owned).** Step 13 never emits `HUMAN_CONFIRM`, `HUMAN_CORRECT`, or `HUMAN_REJECT`; it consumes them as frozen lifecycle facts and specifies phase-correct re-entry (VS-REVIEW-3; §46.15).
**VS-CORE-5 (technical failure ≠ verdict).** Model/API unavailability, parser crash, timeout, malformed raw model response, internal checker failure before a semantic result, or work-product serialization fault never emits any VERIFICATION_* event, never mutates canonical semantics, and leaves the round incomplete under the frozen lifecycle — retried idempotently against the same locked round inputs where lawful; if record state/revision/epoch changed before retry, the old result is stale and the frozen transition/restart rules apply. Infrastructure failure is never presented to a human as semantic uncertainty.

When Step 13 detects a correctable semantic problem → review; it never repairs the canonical record itself.

## 46.5 Verifier independence — operational contract

**VS-INDEP-1 (lawful verifier inputs).** The semantic verifier runs as a fresh verification invocation and may receive: the canonical `gap_record`; the `gap_processing_envelope` fields required for verification; the pinned `document_id` + `document_version`; the record's authoritative `source_spans`; the exact manuscript snapshot needed to validate those spans; recorded context-support spans / lawful local co-text needed to evaluate contextual completion; section/paragraph/section-role information; contributing Step-11 extraction-instance source representations where required for lineage verification; relevant candidate/routing records where needed to verify provenance; the CURRENT closed-epoch canonical comparison universe where GI verification requires it; the current `closure_id`; the current Step-12 `RESOLUTION_COMPLETE` attestations; Citation Registry state/version where reference-resolution verification requires it; all frozen semantic rules needed for verification; human-confirmation records where a prior review must be respected — a prior HUMAN_* event is a frozen lifecycle fact, not model reasoning.
**VS-INDEP-2 (prohibited verifier inputs; what independence is).** The verifier MUST NOT receive: extractor chain-of-thought; extractor free-text rationale; detector confidence; Step-11 model rationale; Step-12 reasoning/rationale; "why the extractor chose X" notes; previous verifier chain-of-thought; a previous verifier's suggested answer; downstream A.1-C/A.1-A judgments. Independence = fresh invocation + independent verifier instructions + no extractor/resolver rationale + no hidden shared reasoning state + evidence-and-frozen-rule grounding only. Independence does NOT require a different model provider; "different vendor" is not part of this normative specification.

## 46.6 Runtime input contract

**VS-INPUT-1 (minimum lawful round start).** `VERIFICATION_STARTED` requires: `gap_id`; `gap_record`; `gap_processing_envelope`; `run_id`; `document_id`; `document_version`; the exact current document snapshot; `lifecycle_state_code = resolved`; `expected_current_state = resolved`; `expected_state_revision` = current record `state_revision`; no other active verification round; `round_id`; `verifier_suite_version`; the current `gap_run` state; the current `closure_id`; the current `RESOLUTION_COMPLETE` attestation; the `spawn_reference_freeze_stable` attestation; the `identity_routing_freeze_stable` attestation with its citation of the CURRENT `closure_id`; relevant frozen component versions; relevant source/context evidence; Citation Registry state/version where required. No new canonical field is invented for any of these — values belong in State-Machine event/audit storage or the noncanonical verifier work product.
**VS-INPUT-2 (structural start failures).** Structural invocation failure is never `VERIFICATION_REVIEW_REQUIRED`: wrong lifecycle state, a round already active, stale `expected_state_revision`, a stale closure epoch at round start, missing mandatory start payload, or document/version mismatch → the exact frozen State-Machine failure/rejection behavior; no verifier round starts.

## 46.7 Round identity and payload lock

**VS-ROUND-1 (frozen start event; harness mint order).** `VERIFICATION_STARTED` uses the frozen event exactly — producer Step-13 harness; required semantic payload `round_id` + `verifier_suite_version` — and, like every emitted transition request, carries the frozen generic fields `expected_current_state` and `expected_state_revision`. The harness mints `round_id` and pins `verifier_suite_version` BEFORE constructing the `VERIFICATION_STARTED` request; V-1 validates that constructed request, and they are never minted a second time. The frozen transition audit records `closure_id` on every `RESOLUTION_COMPLETE`, `VERIFICATION_STARTED`, and `VERIFICATION_PASS` entry, exactly as frozen (SM v1.3 transition-audit schema).
**VS-ROUND-2 (round binding).** The round is bound, in the verifier's noncanonical/audit work product, to at least: `round_id`; `gap_id`; `document_id`; `document_version`; record `state_revision` at round start; the semantic payload digest; the current `closure_id`; `verifier_suite_version`; the frozen dependency versions. None of these is added as a GS-1.4 field unless it already exists there.
**VS-ROUND-3 (semantic lock).** The semantic `gap_record` is locked for the duration of the round; no canonical semantic mutation may occur while `verifying`.

## 46.8 Noncanonical Step-13 work product

**VS-TRACE-1 (verification bundle).** The `step13_verification_bundle` is a noncanonical work product — not a `gap_record`, not a new GS artefact — existing to make the verifier auditable. It represents at minimum: `round_id`; `gap_id`; `semantic_payload_digest`; document/version binding; `closure_id`; `verifier_suite_version`; `check_results[]` with per-check `verifier_id`, verdict, detail/basis code, source/evidence refs used, and frozen rule IDs used; the aggregate verdict candidate; execution status; technical-error information where applicable. Chain-of-thought is never persisted: audit evidence is source refs + rule IDs + structured result codes + concise observable facts. During the round the bundle is used instead of repeatedly mutating `gap_processing_envelope`; the observable verifier results commit to the envelope atomically with the completed-round State-Machine event.

## 46.9 Aggregation precedence

**VS-AGG-1 (deterministic aggregation).** For a completed round: (1) if ANY mandatory verifier produces a lawful fatal `reject` → aggregate = reject; (2) ELSE if ANY mandatory verifier produces `review_required` OR any contract-required blocking human confirmation is absent → aggregate = review_required; (3) ELSE if EVERY mandatory verifier = `pass` AND every §32.7-F freeze prerequisite holds → aggregate = pass; (4) ELSE the round is not semantically complete — no VERIFICATION_* completion event is emitted until the technical execution is completed/retried. A technical execution failure is never converted into pass, review_required, or reject (VS-CORE-5).

## 46.10 Mandatory verification check families

**VS-SOURCE-1 (schema/source integrity).** Verify: the canonical record validates against `A1E-GS-1.4`; `document_id`/`document_version` match the pinned snapshot; every `span_ref` resolves inside the record's `source_spans` pool; char offsets match the exact pinned manuscript snapshot; span text is verbatim; no cross-artefact span reference is treated as local; required traces exist; exactly one `primary` gap_evidence assertion exists; restatement/corroborating roles are structurally lawful. A failure proving record corruption may be fatal only under VS-REJECT-1; a correctable semantic/span mismatch routes to review.
**VS-BOUND-1 (study-positioning/boundary).** Independently apply the frozen Contract + `A1E-BR-1.2`: the canonical primary claim is an asserted deficiency, in prior knowledge / knowledge structure, a study-positioning gap for the present study — GAP rather than MOTIVATION / OWN_LIMITATION / FUTURE_RESEARCH / CONTRIBUTION / OTHER / UNCERTAIN — with eligible positioning-context requirements verified. Later restatements may lawfully occur outside the original positioning section; a lawful later restatement is never rejected merely for occurring in Results/Discussion/Conclusion.
**VS-BOUND-2 (leakage).** Contribution/objective leakage is tested explicitly: "This study contributes by…", "Our objective is…", "We examine…", "Future work should…", "Our sample is limited…" are never silently verified as GAP unless the same proposition independently satisfies the frozen GAP rule. Topical overlap never suffices.
**VS-EXPL-1 (explicitness/context support).** Verify `explicit` vs `context_supported` exactly under the contract. For `context_supported`: the deficiency predicate must still be asserted; context may complete linguistic arguments; context must not create the deficiency; antecedent/support refs must be sufficient; failed completion is never silently reconstructed. A materially underdetermined current reading → `review_required`. A record existing only because prohibited reconstruction created the gap → fatal handling under VS-REJECT-1.
**VS-PRIM-1 (relation + knowledge_kind).** Independently apply `A1E-DPR-1.1`: exact relation ∈ {ABSENT, LIMITED, CONFLICTING, UNTESTED, CONSTRAINED, DISCONNECTED, CHALLENGED}; exact knowledge_kind ∈ {evidence, theory, method, practice_alignment, unspecified}; `source_trace_refs` support both; the weakest-supported reading is preserved — never upgrade LIMITED → ABSENT; never force a kind where `unspecified` is correct. A disagreement correctable while retaining a lawful GAP → `review_required`.
**VS-OBJ-1 (affected object).** Independently apply `A1E-OR-1.1`: `affected_object` is manuscript-grounded; `object_kind` supported; `artifact_kind` supported when required; mention refs identify the asserted object; object-denoting vs carrier/reference anaphora handled per frozen rules; the nonexistent-measure vs existing-constrained-measure distinction respected; generated descriptors never ground object identity; scope/context wording is never structurally converted into an A.1-E scope object. `object_scope_boundary` remains a contract-reserved verification/review flag; a genuinely unresolved object-vs-scope boundary → `review_required`.
**VS-PROP-1 (preserved proposition + normalization).** Verify: `assertion_span_refs` contain the complete asserted deficiency proposition; required proposition arguments preserved; contextual restrictions preserved in wording; normalized text faithful; every normalized substantive element traceable to source; normalization introduces no unsupported proposition, does not strengthen the relation, does not erase an identity-material restriction, and contains no scientific-truth or novelty judgment. Unsupported or paraphrase-altering normalization → `review_required` unless VS-REJECT-1 applies.
**VS-CONTRAST-1 (contrast faithfulness only).** For `reported`: entries source-grounded; cited works / attributed propositions captured faithfully. For `not_reported`: a valid canonical state; absence is not itself proof of extraction failure. The contract-reserved `contrast_not_reported` flag is NONBLOCKING by itself when the `not_reported` state is lawful. Absence of a contrast is never turned into a scientific-quality judgment; external literature is never searched for a missing contrast.
**VS-CITE-1 (citation reference capture only).** For every citation link — resolved: the recorded Registry result matches the pinned Citation Registry resolution state/version; unresolved: `registry_citation_id` absent, durable verbatim citation text preserved, the unresolved state faithfully recorded. Step 13 never assesses whether the cited source supports the gap, is credible, or is scientifically appropriate — downstream Citation/Literature Validation owns those.
**VS-CITE-2 (unresolved citation — mandatory human confirmation; frozen by the Contract).** If any citation remains unresolved AND that exact unresolved citation has not received the required human faithful-capture confirmation → `review_required` → `VERIFICATION_REVIEW_REQUIRED` → open/retain `citation_unresolved`. No automatic verifier PASS substitutes for this confirmation. After `HUMAN_CONFIRM`: `verification_review_required` → `resolved`, and a FRESH `VERIFICATION_STARTED` is mandatory; only that fresh round may PASS. Human confirmation means only "the verbatim unresolved citation was captured faithfully" — never "the citation supports the manuscript claim."
**VS-PERSIST-1 (persistence + spawn).** Verify: persistence reasons source-grounded; causal explanation alone never becomes another gap; only an independently asserted deficiency produces a spawn; every qualifying spawn used the ordinary candidate lifecycle; no seed was promoted directly into a `gap_record`; `spawned_claim_ref` structurally lawful; `reason_of` established only between lawful canonical claims at the authorized layer and directional; duplicate spawned gap identity reconciled per GI. Step 13 never creates or repairs a spawn; a discrepancy → normally `review_required`.
**VS-IDENT-1 (identity/merge/restatement/links).** Independently apply `A1E-GI-1.0` against the CURRENT closed comparison universe supplied by Step 12 — never expanded. Verify at minimum: SAME_GAP conditions applied exactly; bare triple alone never caused merge; COMPLETE_PROPOSITION_INPUT restrictions preserved; materially distinct claims remain separate; IDENTITY_UNRESOLVED was not merged; the canonical cluster obeys complete-linkage/consistency; GI-CLUSTER-3 processing-order invariance; GI-CLUSTER-4 closure-epoch fixpoint; GI-REP-1/2/3 canonical representative supplying the ENTIRE canonical semantic payload; exactly one `primary` assertion; merged assertions are lawful restatements/corroborating evidence; POSSIBLE-A and POSSIBLE-B `possibly_same_claim` links correct; `related_claim` links correct; symmetric links reciprocal with no one-sided link; `reason_of` directional; ATTACHED instances actually SAME_GAP with their target; CREATED instances not required to ATTACH under frozen GI.
**VS-IDENT-2 (detect, never fix).** Step 13 may independently detect a Step-12 identity error; it never fixes the identity topology itself. A correctable identity/routing discrepancy → `review_required` → the human-correction / Step-12 rerun pathway.
**VS-LINEAGE-1 (lineage/routing consistency).** Verify structural correspondence where available: `promoted_from_candidate_ids` refer to real candidate lineage; CREATED routing entries target the correct `gap_id`; ATTACHED entries target the correct canonical record; terminal candidate routing is consistent with the canonical records; no extraction instance has conflicting terminal dispositions; no canonical record relies on a candidate whose lifecycle facts make the linkage impossible. Missing lineage is never reconstructed by inference.
**VS-PROHIB-1 (contract-prohibited content).** Verify the canonical A.1-E semantic payload contains no: structured Scope/Context; A.1-C type/mode/construction judgment; A.1-A validity/importance/novelty judgment; citation-support judgment; quality score; mandatory confidence value; scientific truth assessment; inferred external object relation presented as manuscript fact. Impossible upstream-state corruption is treated separately from ordinary semantic review.

## 46.11 Freeze prerequisites — exact §32.7-F gate

**VS-FREEZE-1 (eight prerequisites).** `VERIFICATION_PASS` is forbidden unless ALL frozen prerequisites hold, checked by Step 13: (1) the canonical `gap_record` is schema-valid; (2) A.1-E-owned resolution is complete — `RESOLUTION_COMPLETE` exists and has not been retracted; (3) no blocking review requirement is open; (4) the active verification round matches the event `round_id`; (5) contract-required unresolved-citation faithful-capture human review is complete where applicable; (6a) every `spawned_claim_ref` is freeze-stable; (6b′) identity/routing freeze-stability is attested AND the attestation cites the run's CURRENT closure epoch; (7) no outstanding semantic-mutation task exists — no pending correction, no pending lawful restatement attachment, no unresolved mutation that must alter the canonical record; (8) external Research Structure object canonicalization is irrelevant — missing/provisional/completed external object resolution neither satisfies nor blocks verification.
**VS-FREEZE-2 (triple epoch gate; staleness).** The frozen v1.3 triple epoch gate checks the current epoch at `RESOLUTION_COMPLETE`, `VERIFICATION_STARTED`, and `VERIFICATION_PASS`; Step 13 owns the latter two checks only. At `VERIFICATION_STARTED`: if the record's identity attestation does not cite the CURRENT `closure_id` → verification does not start; the exact frozen illegal/stale-attestation path applies; Step-12 retraction/resolution must occur first. During an already-running round: if `CANDIDATE_UNIVERSE_REOPENED` invalidates the cited epoch, `VERIFICATION_PASS` becomes structurally impossible; the in-flight round never freezes the record; the frozen legal path from `verifying` applies — normally `VERIFICATION_REVIEW_REQUIRED` with the verification-owned stale-epoch reason (`verification_epoch_stale`), never pretending the semantic extraction failed. The subsequent lifecycle still forces Step-12 re-attestation before any future PASS. Step 13 never emits `RESOLUTION_BLOCKED` — that remains Step-12 ownership.

## 46.12 Reserved review flags

**VS-REVIEW-2 (reserved-code reconciliation).** `citation_unresolved` — blocking until the exact faithful-capture `HUMAN_CONFIRM` exists (VS-CITE-2). `object_scope_boundary` — blocking while semantically unresolved; `HUMAN_CONFIRM` may confirm the current extraction; `HUMAN_CORRECT` may change it; fresh verification required either way. `contrast_not_reported` — nonblocking by itself when the extracted `not_reported` status is lawful; observable provenance, never a quality judgment. One Step-13-owned addition: `verification_epoch_stale` (VS-FREEZE-2). No duplicate synonymous flags exist.

## 46.13 Review-required principle

**VS-REVIEW-1 (conservative outcome).** `REVIEW_REQUIRED` is the conservative outcome for: material verifier disagreement where a lawful GAP may still remain; boundary/semantic underdetermination; `object_scope_boundary`; relation/kind disagreement; object disagreement; proposition/normalization discrepancy; identity/routing discrepancy; an unresolved citation awaiting required confirmation; canonical-representative discrepancy; a source-grounding problem that may be correctable; a stale epoch discovered during an active round; any semantic problem requiring human judgment before the record may freeze. Review is never a technical retry mechanism, a confidence band, or a scientific-quality rating.

## 46.14 VERIFICATION_REJECT — narrow fatal rule

**VS-REJECT-1 (closed fatal policy).** `reject` is lawful only when the available frozen evidence and rules deterministically establish a fatal pre-verification defect such that the current record cannot lawfully remain an A.1-E gap record. Closed fatal codes: **F-VS-NON-GAP** (DETERMINISTIC_NON_GAP — the source proposition is deterministically non-GAP under `A1E-BR-1.2` and no lawful GAP reading remains); **F-VS-PROHIBITED-RECONSTRUCTION** (the canonical gap exists only because a deficiency was invented from objectives, RQs, contribution language, pragmatic implication, or another explicitly prohibited reconstruction path); **F-VS-FABRICATED-ASSERTION** (canonical semantic content claims a manuscript assertion demonstrably absent from the pinned source snapshot, not explainable as a correctable span-boundary issue). REJECT is never broadened into "severe error": if the record may lawfully remain a GAP after correction → `REVIEW_REQUIRED`. Never rejected for: unresolved citation; `contrast_not_reported`; missing external object canonicalization; `object_scope_boundary` ambiguity; correctable relation/kind disagreement; rerunnable identity disagreement; scientific weakness; lack of novelty; lack of importance.

## 46.15 Human review — consume, do not own

**VS-REVIEW-3 (phase-correct re-entry).** From `verification_review_required`: `HUMAN_CONFIRM` → `resolved` → a fresh `VERIFICATION_STARTED` is mandatory. `HUMAN_CORRECT` → `structured` → Step 12 must rerun to `RESOLUTION_COMPLETE` → `resolved` → fresh `VERIFICATION_STARTED`. `HUMAN_REJECT` → `rejected`. Remaining unresolved → `verification_review_required`. No human outcome directly produces `extraction_verified`; no human confirmation bypasses a fresh verifier round. If `HUMAN_CORRECT` introduces a new spawn assertion, Step-12/candidate-universe reopening applies downstream exactly as frozen — Step 13 never reopens the universe itself.

## 46.16 Human-review status codes

**VS-BASIS-2 (human_review_status_code registry).** GS-1.4 provides `human_review_status_code: code(VERIFICATION_SPEC)`, ABSENT lawful where no human review applies. Closed vocabulary: `confirmation_pending`; `confirmed`; `corrected`; `rejected_by_human`. When human review is not applicable the field is ABSENT — per frozen GS-1.4 there is no stored not-applicable status; ABSENT is the sole representation of that state. The event/audit history is authoritative; the code is observable status, never a substitute for the actual HUMAN_* lifecycle events, and never encodes free-form reviewer reasoning.

## 46.17 Verification basis codes

**VS-BASIS-1 (closed basis registry).** Basis codes answer "what was independently established before this record froze?" Closed set: `VB-SOURCE` (source/span integrity); `VB-BOUNDARY` (GAP positioning/boundary); `VB-EXPLICITNESS` (explicitness/context completion); `VB-RELATION`; `VB-KIND`; `VB-OBJECT`; `VB-PROPOSITION` (complete proposition); `VB-NORMALIZATION`; `VB-CONTRAST` (contrast capture); `VB-CITATION-REF` (citation-reference capture); `VB-PERSISTENCE` (persistence/spawn handling); `VB-IDENTITY` (identity/routing); `VB-REPRESENTATIVE` (canonical representative); `VB-FREEZE` (freeze-prerequisite satisfaction). No probabilities are encoded; basis codes are never a hidden score. On `VERIFICATION_PASS`, `verification_basis_codes` represent the basis of the successful CURRENT round — stale basis codes from an earlier review round never masquerade as the final PASS basis. Before semantic freeze they are mutable workflow metadata; at `extraction_verified` they describe the successful final round.

## 46.18 verifier_results semantics

**VS-TRACE-2 (existing GS structure, unchanged shape).** `verifier_results: [{verifier_id, verdict_code, detail_code?, at}]` — `verifier_id` identifies the mandatory verification check/component; `verdict_code ∈ {pass, review_required, reject}`; `detail_code` is Step-13-owned and explains the observable check result; results are append-only history unless the frozen schema says otherwise; round grouping lives in State-Machine transition/audit provenance — no `round_id` is invented inside `verifier_results`. A verifier_result never modifies the semantic `gap_record`.

## 46.19 State / revision protection

**VS-STATE-1 (frozen request fields; exact expected states).** Every Step-13 transition request carries the frozen `expected_current_state` and `expected_state_revision`: `VERIFICATION_STARTED` — expected_current_state = `resolved`; `VERIFICATION_PASS` / `VERIFICATION_REVIEW_REQUIRED` / `VERIFICATION_REJECT` — expected_current_state = `verifying`. Any stale `expected_state_revision` → `rejected_stale`, zero transition effects. Wrong state → the exact frozen illegal-transition result. Wrong `round_id` → the exact frozen failure; the intended round is never inferred.
**VS-STATE-2 (revision race).** A semantic verifier result computed against record revision N never commits against revision N+1: reload and rerun/re-evaluate as required.

## 46.20 Atomic completion

**VS-ATOM-1 (completed-round transaction).** A completed round atomically includes the applicable: final `verifier_results` writes; `verification_basis_codes` update; review flags opened/resolved where Step 13 owns the effect; the verification verdict event; envelope audit update; lifecycle transition; `state_revision` transition effects. PASS: `verifying` → `extraction_verified`, semantic freeze activating atomically. REVIEW: `verifying` → `verification_review_required`, required blocking review flags opening atomically. REJECT: `verifying` → `rejected`, the fatal audit result retained atomically. No partial state: no PASS basis without the PASS transition; no `extraction_verified` without a successful PASS; no review state without its review result; no reject event without its fatal result.

## 46.21 Deterministic procedure

**VS-PREC-1 (closed ordered procedure; labels procedure-internal, never pseudo-rules).** V-1 validate the constructed invocation/request (VS-INPUT-1/2; `round_id` and `verifier_suite_version` already minted/pinned by the harness per VS-ROUND-1). V-2 validate `expected_current_state` / `expected_state_revision`. V-3 validate record = `resolved`. V-4 validate the current closure epoch (VS-FREEZE-2). V-5 validate the current `RESOLUTION_COMPLETE` dual attestations. V-6 bind/confirm the already-minted `round_id` and pinned `verifier_suite_version` — never minted a second time. V-7 emit `VERIFICATION_STARTED`. V-8 bind the semantic payload digest / source snapshot / frozen versions (VS-ROUND-2). V-9 run the schema/source integrity verifier (VS-SOURCE-1). V-10 run the positioning/boundary verifier (VS-BOUND-1/2). V-11 run the explicitness/context verifier (VS-EXPL-1). V-12 run the relation/kind verifier (VS-PRIM-1). V-13 run the affected-object verifier (VS-OBJ-1). V-14 run the proposition/normalization verifier (VS-PROP-1). V-15 run the contrast/citation-reference verifier (VS-CONTRAST-1; VS-CITE-1). V-16 enforce the unresolved-citation human-confirmation rule (VS-CITE-2). V-17 run the persistence/spawn verifier (VS-PERSIST-1). V-18 run the GI identity/routing/representative verifier (VS-IDENT-1/2). V-19 run the lineage/routing consistency verifier (VS-LINEAGE-1). V-20 run the prohibited-content verifier (VS-PROHIB-1). V-21 re-check the current epoch. V-22 re-check all §32.7-F prerequisites (VS-FREEZE-1). V-23 aggregate mandatory verifier outcomes (VS-AGG-1). V-24 technical incomplete → no completion event; retry (VS-CORE-5). V-25 fatal aggregate → `VERIFICATION_REJECT`. V-26 review aggregate → `VERIFICATION_REVIEW_REQUIRED`. V-27 pass aggregate + all freeze prerequisites → `VERIFICATION_PASS`. V-28 atomically persist the observable verification result (VS-ATOM-1). V-29 STOP round.
