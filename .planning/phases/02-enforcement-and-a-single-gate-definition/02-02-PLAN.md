## The named hazard: recursion

**This is the failure this plan is designed around, not one to discover during
execution.** A test that shells out to a Make target, running inside the suite that
target invokes, recurses:

```
make test → go test ./... → internal/platform/gate test → make test → go test ./... → …
```

Each level costs a full suite run. Nothing in the design shows it until it happens,
and when it happens a 30-second test run becomes a hung machine.

Both of this plan's assertions sit on that path. D-05's banner assertion invokes
`make test`, which is the loop above directly. D-03's voicelessness assertion
invokes `make env-preflight`, which runs `go test ./internal/platform/testenv/` —
that does not include this package today, so it does not loop today, but Phase 3
will invoke `make gate`, and `gate` calls `$(MAKE) test`, which does. The guard is
therefore built into the harness for **every** target, not bolted onto the one
target that loops right now.

**The guard.** `harness.Run` sets `EPISTEMIC_OS_TEST_MAKE_DEPTH` in every child's
environment to the parent's depth plus one. Every test in this package calls
`gate.SkipIfNested(t)` as its first statement; at depth ≥ 1 it declines. The loop
terminates at depth 1, costing exactly one extra suite run.

**The guard's own failure modes are closed, both directions:**

| Marker value | Naive handling | Why it is wrong | What the guard does |
|---|---|---|---|
| unset / empty | depth 0, run | correct | depth 0, run |
| `1`, `2`, … | depth n, decline | correct | depth n, decline |
| `abc`, `-1` | treat as 0 | recurses — the hung machine | **hard fail**, naming the variable and its value |
| `abc`, `-1` | treat as nested | skips silently — a vacuous pass, this milestone's own defect | **hard fail**, naming the variable and its value |

A malformed marker is the one case where both convenient answers are wrong, so it
is neither: it fails loudly. `nestingDepth` is a pure function and its table test
drives all of these with synthetic inputs, so the rule is deliberate rather than
accidental — the same shape `Required()`/`TestRequired` and
`preambleInvariant`/`TestPreambleInvariant_Control` already use in this repository.

**A second, shorter recursion path, closed by placement rather than by the marker.**
D-04's `env-preflight` runs `go test ./internal/platform/testenv/` with no filter.
Had this harness been placed in that package, the preflight would invoke it
directly: `make gate` → `env-preflight` → the harness → `make …` → … . That is why
this package is `internal/platform/gate` and not a new file under `testenv`.

## Decisions this plan makes (planner's discretion, flagged for review)

CONTEXT.md left the harness's location and shape to the planner (PATTERNS.md: "file
path is the planner's decision, not fixed here"). Phase 3 binds to all of these.

1. **Package path `internal/platform/gate`**, holding `harness.go` (non-test Go
   importing `testing`, the same shape `testenv` already uses and which Phase 1
   verified builds, vets and formats clean), plus two test files. Chosen over a new
   top-level `test/` directory to keep the existing three-way `internal/` split
   intact, and over `internal/platform/testenv` for the recursion reason above.
2. **`Run(t, argv, opts)` is the primitive and `Make(t, target, opts)` wraps it.**
   The voicelessness assertion needs to run both `make env-preflight` and the bare
   `go test` command it wraps, and compare them; a make-only API could not express
   the second half.
3. **Streams are captured separately**, not combined. D-03's constraint is about the
   step's own stdout *and* stderr, and separate capture also removes the
   interleaving nondeterminism a single combined buffer would introduce into a
   line-by-line comparison. `RunResult.Combined` is provided for convenience and is
   `Stdout + Stderr`, not a third capture.
4. **`DefaultTimeout` is 4 minutes**, deliberately below `go test`'s 10-minute
   per-package default so a hung child is attributed to the child. Measured basis:
   a full `go test ./... -count=1` is ~13 seconds on this host with the database up,
   and `make vet` alone is ~35 seconds, so 4 minutes is roughly six times the
   slowest plausible child.
5. **The voicelessness comparison is differential, not textual.** D-07 rejected
   static Makefile-text assertions on a non-uniform-weakness argument: the likely
   decay is a tool inside the step starting to print, which a text check cannot
   see. So the assertion compares the Make target's real output against the real
   output of the command it wraps, and reports any line present in the first and
   absent from the second.
</objective>

## Verified ground truth

Measured in this repository at `c2ec2d6` before planning, by running the commands.

- **A Go test can invoke `make` and read its output.** A probe test in
  `internal/platform/zzprobe` walked up from the package directory to the first
  directory containing `go.mod`, ran `exec.Command("make", "help")` with `cmd.Dir`
  set to it, and got exit 0 and the expected first line. The probe was deleted.
- **A directory containing only `_test.go` files is fine.** `go build ./...`,
  `go vet` and `gofmt -l` all pass over such a package, and `go test` runs it.
  Verified with the same probe. This plan nonetheless puts the harness in a
  non-test file so Phase 3 can import it.
- **`make -s` fully suppresses recipe echoing.** With `-s`, `make quiet` (a target
  whose recipe is `go test ./internal/platform/testenv/ -count=1`) emitted exactly
  one line, `ok\tgithub.com/EpistemicOS/epistemicos/internal/platform/testenv\t1.167s`
  — byte-identical to the direct `go test` output except for the elapsed time.
- **The differential assertion can come back false.** The same probe makefile with
  an `@echo` added to the recipe emitted that extra line and nothing else changed.
  So the comparison distinguishes a voiceless recipe from a speaking one.
- **Make's own diagnostics go to stderr and are identifiable.** On a failing
  recipe make writes lines of the form `make: *** [Makefile:12: gate] Error 2` and,
  for sub-makes, `make[1]: …`. They are Make's voice, not the recipe's, and the
  comparison must drop lines matching `^make(\[[0-9]+\])?: ` from the Make side
  before comparing.
- **Output is deterministic modulo elapsed times.** A failing run of
  `go test ./internal/adapters/secondary/approved/ -count=1` against a closed-port
  DSN printed stable text with only `(0.01s)`-style per-test elapsed values and a
  trailing `FAIL\t<pkg>\t2.517s` varying between runs.
- **The unreachable-database condition needs no Docker.**
  `postgres://u:pw@127.0.0.1:1/nodb?sslmode=disable` is a closed local port;
  `pgxpool.New` returns nil and the failure surfaces at `Ping`. Nothing has to be
  stopped, so this assertion does not disturb a running compose service.
- `go test ./... -count=1` is ~13 seconds with the database up and reports 0 skips.
  One nested suite run is therefore an acceptable cost, and is D-04's already
  accepted "runs twice" cost extended by one more level.

naming the depth and saying that this is a nested Make invocation and the outer run
owns the assertion.

`RepoRoot(t *testing.T) string` — walks up from `os.Getwd()` to the first directory
containing `go.mod`, `t.Fatalf` if it reaches the filesystem root.

`RunOptions` — struct with `Env []string` (`KEY=VALUE` entries layered onto
`os.Environ()`), `Unset []string` (variable names removed from the child
environment), `Timeout time.Duration` (zero means `DefaultTimeout`), and `Silent
bool` (adds `-s` on the `Make` path).

`RunResult` — struct with `Stdout string`, `Stderr string`, `Combined string`,
`ExitCode int`, `TimedOut bool`. `Combined` is `Stdout + Stderr`, not a third
capture; say so in its doc comment, because a caller who assumes interleaved
ordering would be wrong.

`Run(t *testing.T, argv []string, opts RunOptions) RunResult` — builds the child
environment from `os.Environ()` by removing every name in `opts.Unset`, applying
every entry in `opts.Env`, and setting `DepthEnv` to the current depth plus one.
Uses `exec.CommandContext` with a `context.WithTimeout`, `cmd.Dir = RepoRoot(t)`,
and two separate `bytes.Buffer` writers for stdout and stderr. Reports `TimedOut`
when the context deadline was exceeded, and extracts `ExitCode` via
`*exec.ExitError` (a non-`ExitError` error is a `t.Fatalf`, since it means the
child could not be started at all — that is a broken environment, not a test
outcome). It must not `t.Fatal` on a non-zero exit code: a non-zero exit is the
expected outcome for most callers here and for all three of Phase 3's proofs.

`Make(t *testing.T, target string, opts RunOptions) RunResult` — `Run` with
`argv` of `make`, optionally `-s`, then `target`.

`normalizeElapsed(s string) string` — replaces Go test elapsed-time tokens with a
fixed placeholder so two runs of the same command compare equal. Cover both shapes
measured on this host: a parenthesised per-test elapsed such as `(0.01s)`, and a
tab-separated trailing package elapsed such as `\t2.517s`.

`extraLines(got, want string) []string` — splits both on newlines, normalizes each
side with `normalizeElapsed`, drops lines from `got` matching Make's own diagnostic
prefix (`make:` or `make[N]:`, since those are Make's voice and not the recipe's),
and returns the lines of `got` not accounted for by `want`, compared as multisets
so a line printed twice is reported once as extra. Empty result means `got` said
nothing `want` did not.

**`harness_test.go` contents** — table-driven tests for each pure function, driving
them with synthetic inputs rather than through the environment or a subprocess, per
the pattern Phase 1 established: `TestNestingDepth` over the eight values in the
